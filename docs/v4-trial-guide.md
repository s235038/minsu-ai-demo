# 台東旅宿 V4 展示與七天試用手冊

這份手冊供民宿、飯店、汽車旅館的業主與櫃台同仁使用。請以虛構情境演練常見問答、需求摘要和櫃台交接。

## 開始試用

1. 從整合 PR 的成功 Actions 執行頁下載 `hospitality-demo-html`，解壓縮後用瀏覽器開啟 `minsu_ai_v3.html`。手機的檔案預覽若只顯示靜態頁面，可先在桌面瀏覽器操作，並記下手機型號、瀏覽器和開啟方式。
2. 在「老闆管理區」展開「業者試用指南」，再切到「旅客接待」。選一個與業態相關的問題，查看回覆是否符合櫃台需求。
   - 民宿可試問「可以帶狗嗎？可以包棟嗎？」
   - 飯店可試問「有停車嗎？可以寄放行李嗎？」
   - 汽車旅館可試問「有什麼房型？有休息方案嗎？」實際時段與費用由櫃台確認。
3. 按「開始示範諮詢」和「使用示範日期」。也可展開手動表單。核對摘要後按「送至示範後台」及「查看後台」，把狀態改成「處理中」，確認後改為「已處理」。
4. 在工作台修改一則只含虛構內容的 FAQ，填寫展示旅宿名稱，再按「下載客製展示 HTML」。重新開啟 `minsu-trial.html`，重問同一題確認修改有帶入。

## 五分鐘展示腳本

| 時間 | 操作與說明 |
| --- | --- |
| 0:00–0:45 | 開啟展示檔，依業態選一組常見問題。說明櫃台可以編輯回答，旅客可在同一句提出兩個問題。 |
| 0:45–2:00 | 輸入「想住 2 或 3 晚，2 位大人、1 位小孩，想要家庭房」。按畫面提示提供完整示範日期及單一晚數，核對摘要上的資訊與「尚未訂房」。 |
| 2:00–3:15 | 送至示範後台。將需求由「待確認」改為「處理中」，說明櫃台須查核空房、報價及特殊需求，再依自己的作業流程回覆。 |
| 3:15–4:30 | 修改一則 FAQ、下載客製 HTML 並重開。請業者在新檔用自己的話重問一次。 |
| 4:30–5:00 | 請業者指出最省時間與最卡的一步，邀請以指定情境完成七天試用。 |

## 十題業者訪談

1. 一般日與旺季每天各有多少則重複詢問？
2. 電話、訊息、現場詢問中，哪個管道最耗櫃台時間？
3. 最常被問的三題是什麼？哪些答案會隨日期、房型或時段變動？
4. 處理一筆完整住宿或休息諮詢平均要多久？
5. 旅客最常漏填哪一項資料？補問通常需要幾輪？
6. 哪些問題一定要立刻轉人工？值班人員如何接手？
7. 什麼情況最容易重複回覆、漏接或跨班交接失敗？
8. 哪位同仁能維護 FAQ？政策變更時怎麼核准和更新？
9. 目前的手動交接、開檔或分享流程，哪一步會阻止你日常使用？
10. 若試用有效，哪個成果會讓你願意付費？能接受的預算、付款方式和決策時點是什麼？

## 七天試用計畫

全程使用虛構輸入和測試裝置。第一天先記錄目前模擬處理一筆詢問的時間作為基準。記錄只留旅宿類型、裝置及瀏覽器、情境、耗時、結果和卡點。

| 日程 | 任務 |
| --- | --- |
| 第 1 天 | 開檔、跑一遍展示，選定三個常見情境及一個必須轉人工的情境。 |
| 第 2 天 | 編輯三則示範答案，確認第二位同仁用不同說法也能取得合適回覆。 |
| 第 3 天 | 在實體 iPhone 和 Android 試開檔、送出、捲動及切換工作台。 |
| 第 4 天 | 測試不完整日期、`2 或 3 晚`、全形人數和未知問題，確認會提示補充或交由櫃台確認。 |
| 第 5 天 | 重複轉交同一未結案需求，切換處理狀態並重新整理，比對清單與計數。 |
| 第 6 天 | 下載、重開、離線問答，測試裝置提供的分享或複製方式。 |
| 第 7 天 | 比較完成率、耗時及人工補問次數，回顧卡點與可接受的價格和服務範圍。 |

建議驗收門檻可在第 1 天和業者調整。初始目標為三個常見情境各自可完成、至少一個人工流程可交接、沒有錯誤的價格或訂房承諾。另記錄使用者在無引導下能否開檔與完成摘要。

## 試用報價草案

以下金額用於訪談驗證，可依旅宿類型、輔導時間與 FAQ 數量調整，尚待確認。試用到期由雙方決定是否繼續。

| 方案 | 試算金額 | 範圍 |
| --- | --- | --- |
| 七天自助試用 | NT$0 | 一份展示檔、試用手冊及回饋清單。 |
| 七天輔導試用 | NT$1,500／一間旅宿，一次性 | 45 分鐘導入、協助整理最多 10 則示範 FAQ、一次 30 分鐘回顧。 |

試算時逐項確認金額是否含稅、支援時段、答覆修改次數、交付日期及後續服務範圍。試用草案無自動續約，未對外承諾價格或收款。正式託管、串接和後續維護須另行確認範圍與價格。

## 限制與風險

- 回覆由規則辨識和可編輯 FAQ 提供。罕見說法可能需要重述或改用手動表單。
- 即時空房、正式報價和訂單由櫃台查核。LINE 官方帳號、訂房平台、生成式 AI 和付款均未串接。
- 工作台資料留在同一瀏覽器。檔案預覽、私密瀏覽或儲存限制可能影響開檔、分享與重整後保留；多裝置交接尚未提供。
- 展示沒有業者帳號或權限隔離。請用虛構名稱、日期和需求，避免輸入姓名、電話、證件、付款資料與金鑰。試用結束後，可在展示工作台清除本機諮詢。
- 實體手機的檔案關聯與分享面板須實機驗證。原型的瀏覽器自動化結果用於回歸檢查。
