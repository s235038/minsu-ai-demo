# V5 商業試用前的隱私與資料刪除驗收門檻

> 狀態：**尚未通過正式客戶資料驗收**。此文件是安全驗收清單，不代表 LINE 已實際串接、生成式 AI 已啟用或產品已正式上線。

## 現有實作的事實（依 V5 程式）

- `v5/demo.mjs`：只監聽 `127.0.0.1`、產生臨時金鑰、使用記憶體 SQLite 與虛構事件；關閉後資料消失。適合第一輪無個資演示。
- `v5/start.mjs`：預設將 SQLite 寫入 `v5/v5-demo.sqlite`，**關閉服務不等於刪除資料**；不得把這個持久化模式與一行展示模式混淆。
- `v5/store.mjs`：案件可刪除；事件去重與統計紀錄仍保留，對話狀態有效期 24 小時且採後續存取時清理，並非到期即由背景工作刪除。
- `v5/server.mjs`：後台 API 使用單一 Bearer 金鑰；尚無業者分租戶與個別操作員權限。不得將後台暴露到公網。
- LINE 原始訊息與原始使用者 ID 不存入 SQLite，但住宿日期、人數等摘要仍可能構成個人相關資訊，應依個資管理。

## 第一階段：僅虛構資料、零外部帳號

1. 使用 Node.js 24 在 Windows PowerShell 或 CMD 執行 `node v5/demo.mjs`；確認畫面標示「模擬 LINE、模擬問答」。
2. 在同一台電腦開啟終端機提供的 `http://127.0.0.1:<port>/operator`；使用本次臨時金鑰登入。切勿截圖、分享金鑰。
3. 以無痕視窗測試：未提供 Bearer 金鑰的 `/api/inquiries` 應回 HTTP 401。
4. 使用虛構日期與人數測試案件「新增 → 處理中 → 已解決 → 刪除」；刪除後重新整理，案件不得再出現在清單。
5. 關閉程式後重新啟動，確認前次虛構案件不再存在。此項只適用 `demo.mjs`，**不可用來推論持久化資料庫已刪除**。

## 第二階段：持久化與刪除（尚待完成，不可拿真實個資測試）

- [ ] 訂出案件、事件去重資料、對話狀態、日誌及備份各自的保存期限，確認資料處理告知與刪除請求流程。
- [ ] 增加可驗證的定期清理機制，包含逾期事件、對話狀態、已結案案件；確認清理不破壞 LINE 重送去重與稽核需求。
- [ ] 驗證刪除後 SQLite 主檔、WAL、備份及匯出資料的處置；不得只用前台清單消失當成全面刪除證據。
- [ ] 每位業者與操作員使用獨立身分及最小權限，加入金鑰輪替與存取稽核，再考慮對外開放。
- [ ] 完成 HTTPS、webhook 驗簽、重送與回覆失敗復原、實體 iPhone 測試後，才申請使用獨立 LINE 測試帳號；不得使用正式客戶帳號。
- [ ] 先取得業者同意、確定成本上限及資料處理方式，再決定是否使用付費模型或外部託管。

## 商業驗收紀錄（每間業者七天，先用虛構測試）

記錄「旅客原始問題類型（不記個資）／是否由核可知識正確回答／是否誤承諾房況價格／是否需要真人／人工接手耗時／完成諮詢耗時」。至少逐題人工抽查，將 **實際節省分鐘數** 與合成評估的假設值分開呈現。只有真實業者驗收、合法資料處理與付費意願得到確認後，才稱為可收費 MVP。
